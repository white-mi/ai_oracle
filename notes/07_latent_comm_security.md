## A1. What do the latent/KV-cache agent-communication papers actually claim, on what setups, with what code?

### Takeaway
All verified latent-communication papers (LatentMAS, C2C, KVComm, Interlat, LCF, MoT, XKV, "See What I See", StateBridge) are evaluated on math, science/commonsense QA, extractive/multi-hop QA or code (plus ALFWorld in Interlat); they need white-box access to hidden states or KV caches, and the heterogeneous ones need trained (or closed-form) alignment modules. Headline gains over text are modest where the comparison is fair (C2C +3.1-5.4%, XKV +3.5 macro points over text-to-text) and the big numbers are efficiency (tokens, latency).

### Inferences
- "Wordless" in practice means (a) hidden-state or KV-cache hand-off, (b) between open-weight models, (c) usually same family, with learned/closed-form adapters when heterogeneous. No verified method yields a communication channel a human auditor can read.
- Fair-comparison gains over text are small (C2C 3.1-5.4%; XKV 3.5 macro points over text-to-text; "See What I See" only "matches or exceeds" text); the large numbers (70-84% fewer tokens, 4x speed, 24x) are cost savings. For an oracle where decision quality and explainability dominate cost, the case for latent channels is weak.
- Most evaluated pairs are small (0.5B-14B), so claims may not transfer to frontier models.

- MoT (2607.28979) exact submission date and any code link not obtained (abs page empty via WebFetch).
- LatentMAS exact backbone count and the "13.3% average" figure unresolved; the 9-benchmark list rests on the README (v2 body extraction differed).
- Code for Interlat, LCF, MoT, "See What I See", KVComm not found on arXiv pages (may exist elsewhere).
- Venue/acceptance of LCF, MoT, XKV, "See What I See": none stated on pages seen.

## A2. KV cache, open-weight requirement, judgment-task coverage, error correlation, auditability

### Takeaway
A KV cache is the per-layer stored key/value tensors of already-processed tokens; latent methods read or splice these tensors, so they need white-box access and a compatible (or learned-aligned) architecture. I found no latent-communication evaluation on fact verification, forecasting or legal judgment over retrieved evidence, no measurement of whether latent channels raise or lower error correlation, and a growing set of 2026 papers showing latent channels are an attack and audit blind spot.

### Cited Findings
- What a KV cache is and why it matters: the vLLM/PagedAttention paper (Kwon et al., SOSP 2023) states "the key-value cache (KV cache) memory for each request is huge and grows and shrinks dynamically" and proposes PagedAttention for near-zero waste and sharing within and across requests. [VERIFIED-PRIMARY (abstract)] — [arXiv:2309.06180](https://arxiv.org/abs/2309.06180). Plain explanation (standard transformer knowledge, my wording): at each layer and attention head, every processed token yields a key vector and a value vector; when generating the next token the model attends over the keys/values of all earlier tokens, so they are stored rather than recomputed. Size scales as 2 x layers x KV-heads x head-dim x tokens x bytes. The original attention mechanism is Vaswani et al. 2017, "Attention Is All You Need" [UNVERIFIED in this session, background knowledge].
- Why open weights: LatentMAS needs the agent to expose last-layer hidden embeddings and read/write layer-wise KV caches (HF transformers; vLLM only via patched internals). [VERIFIED-PRIMARY (README + abstract)] — [GitHub](https://github.com/Gen-Verse/LatentMAS). Hosted text-only APIs do not expose these tensors (my inference from the method description; I did not find a paper that states this exact sentence, the LatentMAS-body extractor said closed text APIs "cannot support this approach").
- Why same/aligned architecture: MoT abstract says KV caches "remain model-specific and cannot be reused across architectures"; "See What I See" says most prior work is "homogeneous, using duplicate copies of the same model" and "avoids the central challenge of cross-model latent alignment"; C2C, LCF, XKV need trained translators/fusers; StateBridge uses a closed-form orthogonal map (training-free, but still hidden-state access); Interlat notes compatible hidden dimensions. [VERIFIED-PRIMARY (abstracts)] — [MoT](https://arxiv.org/html/2607.28979), [2606.13594](https://arxiv.org/abs/2606.13594), [C2C](https://arxiv.org/abs/2510.03215), [StateBridge](https://alphaxiv.org/abs/2608.13317), [Interlat HTML](https://arxiv.org/html/2511.09149v2)
- Task coverage: LatentMAS benchmarks are math/science/commonsense/code plus MedQA ([README](https://github.com/Gen-Verse/LatentMAS)); C2C: OpenBookQA, MMLU-Redux, ARC-C, C-Eval ([HTML](https://arxiv.org/html/2510.03215v2)); XKV: ROPES, MuSiQue, QASC, StrategyQA, HotpotQA-bridge ([HTML](https://arxiv.org/html/2608.20617)); MoT: BoolQ, PubMedQA, SQuAD, NewsQA, Doc2Dial, HotpotQA-E ([HTML](https://arxiv.org/html/2607.28979)); Interlat: ALFWorld, MATH and "no tool use/retrieval" ([HTML](https://arxiv.org/html/2511.09149v2)); the survey states decision-making tasks have minimal coverage ([HTML](https://arxiv.org/html/2606.05711v2)). Closest to evidence pooling: "When Latent Agents Lie" uses HiddenBench (65 records; hidden-profile tasks where specialists hold partial evidence) and HotpotQA (7,405 records; 100-record white-box slice) with Qwen3-4B (primary) and Qwen3-8B. [VERIFIED-PRIMARY (body, extractor)] — [arXiv HTML](https://arxiv.org/html/2606.28958)
- Error correlation / conformity: no paper found that measures correlation of errors under latent vs text communication. Related evidence on homogeneous agents: "Understanding Agent Scaling in LLM-Based Multi-Agent Systems via Diversity" (Yang, Qu, Wen, Shi, Wen, Zhang, Wierman, Gu; arXiv:2602.03794, 3 Feb 2026) reports homogeneous agents saturate because outputs are correlated, "two diverse agents match or exceed" 16 homogeneous ones, performance bounded by an "effective channel count" K*. [VERIFIED-PRIMARY (body, extractor)] — [arXiv HTML](https://arxiv.org/html/2602.03794v1). On oracle-style tasks: three different LLMs reading identical evidence had error correlation r=0.529-0.689 ([Kota 2605.30802](https://arxiv.org/html/2605.30802v1), see B4). C2C itself states weak-sharer noise propagates to a stronger receiver ([HTML](https://arxiv.org/html/2510.03215v2)).
- Auditability/security critiques of latent channels:
  - "When Latent Agents Lie: KV-Cache Integrity in Multi-Agent LLM Collaboration" (Luis Brito, Carlos Baquero; arXiv:2606.28958, 27 Jun 2026; 16 pages). Abstract: a short visible message can accompany a full KV-cache hand-off; "A visible message may look harmless even if the hidden state has been changed." Clean Qwen3-4B 0.338 EM / 0.486 F1 vs 0.231/0.369 text-only. Attacks (body, extractor): semantic false specialist flipped 9/21 clean-correct answers; random latent corruption collapsed 21/21 to near zero; white-box norm-matched gradient attack cut HiddenBench EM/F1 from 0.323/0.471 to 0.077/0.119 and evaded detection; text-only verifiers "audit commitments, not transported KV". Defense = HMAC-SHA256 manifest (774/774 honest accepted, 295/295 tampered rejected) which does NOT stop a compromised-but-authenticated specialist or semantic lying. Code: staged artifact release promised, no link. [VERIFIED-PRIMARY] — [arXiv abs](https://arxiv.org/abs/2606.28958), [HTML](https://arxiv.org/html/2606.28958)
  - "Out of Sight, Not Out of Mind: Unveiling Latent Attack in Latent-based Multi-Agent Systems" (Chenxi Wang, Ruiyang Huang, Jiayan Sun, Lei Wei, Yifan Wu; arXiv:2605.28214). Steering-vector injection into LatentMAS agents' states or KV hand-offs without changing any visible text: planner-node attack 70.8% accuracy drop on GSM8K, critic-to-refiner KV hand-off 84.4% drop (Qwen3-4B primary, Llama-3.2-3B secondary; GSM8K, OpenBookQA, HumanEval+); direction-aware detector 0.849 TPR at 5% FPR, layer-profile monitor 0.944 TPR (edge-level); "text-level safeguards cannot detect" it; detectors "not yet a complete defense". Code: https://github.com/mnmn-f/Out-of-Sight-LatentAttack. [VERIFIED-PRIMARY (body, extractor)] — [arXiv HTML](https://arxiv.org/html/2605.28214v1)
  - "LCGuard: Latent Communication Guard for Safe KV Sharing in Multi-Agent Systems" (Sadia Asif, Mohammad Mohammadi Amiri, Momin Abbas, Prasanna Sattigeri, Karthikeyan Natesan Ramamurthy; arXiv:2605.22786, 21 May 2026): KV caches create "an opaque channel" leaking private inputs; a learned transformation cuts reconstruction-attack success about 65-75% (Qwen3-4B ASR 0.871 to 0.216, helpfulness 0.710); Qwen3 4B/8B/14B, Gemma-2-9B, LLaMA 3B/8B; PrivacyLens, AgentLeak, MAGPIE. No code link. [VERIFIED-PRIMARY (alphaxiv abstract view + body, extractor)] — [alphaxiv](https://www.alphaxiv.org/abs/2605.22786)
  - Interlat's own limitation list says latent content "remains opaque" ([HTML](https://arxiv.org/html/2511.09149v2)); the LatentMAS body extraction found no decoding or inspection mechanism ([HTML v4](https://arxiv.org/html/2511.20639v4)).

### Inferences
- A latent hand-off is, by construction, an unreadable evidence channel: an auditable oracle needs every inter-agent message and every evidence item to be human-readable and hash-logged, which excludes KV/hidden-state channels between decision agents. A text channel can still be attacked (see B), but the attack is inspectable after the fact.
- Same-backbone latent teams are the least diverse possible ensemble; given the diversity result and the oracle error-correlation numbers, expect high correlated error. This is an inference, not measured for latent communication.
- LatentMAS-style gains were shown on tasks with a single correct reasoning chain; nothing shows they survive adversarial or conflicting evidence.

### Gaps
- No evaluation of latent communication on fact verification, forecasting, legal reasoning or retrieved-evidence judgment found (absence claim from search + reading task lists; not exhaustive).
- No measurement of error correlation or conformity under latent vs text communication found.
- Vaswani et al. 2017 not opened here; a primary KV-cache tutorial (e.g. Hugging Face docs) not opened.
- I could not identify any method called "JEV"; searching "JEV wordless agents" returned only the latent-communication papers above (LatentMAS, Interlat, Beyond Tokens). The user's "wordless agents" most plausibly refers to this literature, not to JEPA.

## A3. JEPA for language: what exists, what it is, what the audit found

### Takeaway
JEPA (Joint Embedding Predictive Architecture) is a self-supervised representation-learning architecture/objective family from LeCun's 2022 position paper, not an agent type and not a communication protocol. LLM-JEPA is an extra training loss for LLM fine-tuning/pretraining (no change at inference); VL-JEPA is a vision-language model that predicts text embeddings; and a May 2026 audit found no corrected-significant gain from 22 JEPA-style auxiliaries on one small setting.

### Cited Findings
- LeCun 2022 position paper (OpenReview id BZ5a1r-kVsf, "A Path Towards Autonomous Machine Intelligence"): abstract describes a "configurable predictive world model, behavior driven through intrinsic motivation, and hierarchical joint embedding architectures trained with self-supervised learning". The fetched page showed the abstract only (no title/author/date text), so title and the 2022 version date come from search listings/background. JEPA is proposed for learning world-model representations (primarily perception/prediction), not as a multi-agent protocol. [VERIFIED-PRIMARY (abstract only)] — [OpenReview](https://openreview.net/forum?id=BZ5a1r-kVsf)
- **LLM-JEPA**: "LLM-JEPA: Large Language Models Meet Joint Embedding Predictive Architectures". Hai Huang, Yann LeCun, Randall Balestriero. arXiv:2509.14252, v1 11 Sep 2025, v2 7 Oct 2025; listed as ICLR 2026 (ML Anthology and OpenReview forum GbXKPo9QfH; arXiv page itself shows no venue). Datasets NL-RX, GSM8K, Spider, RottenTomatoes; models Llama3, OpenELM, Gemma2, Olmo; abstract: outperforms standard LLM training objectives "by a significant margin" and is robust to overfitting. [VERIFIED-PRIMARY (abstract)] — [arXiv abs](https://arxiv.org/abs/2509.14252), [ICLR listing](https://mlanthology.org/iclr/2026/huang2026iclr-llmjepa/). Code: [rbalestr-lab/llm-jepa](https://github.com/rbalestr-lab/llm-jepa) (arXiv page) and [galilai-group/llm-jepa](https://github.com/galilai-group/llm-jepa) (ICLR listing); arXiv license CC BY-NC-SA 4.0.
  - Body (extractor): loss = standard next-token loss + lambda x d(Pred(Enc(Text)), Enc(Code)), cosine distance on last-token final-layer embeddings of two "views" of the same content (e.g. natural-language description vs regex/SQL code); predictor implemented with special [PRED] tokens reusing the LLM's weights; reported NL-RX-SYNTH Llama-3.2-1B about 52% to 71%, pretraining 54.38% to 60.59%; training cost roughly 2x (loss-dropout variant reduces); inference unchanged; requires paired views; grid over lambda in {0.5,1,2,4} and k in {0..4}. [VERIFIED-PRIMARY (body, extractor)] — [arXiv HTML v2](https://arxiv.org/html/2509.14252v2)
- **Representation Without Reward: A JEPA Audit for LLM Fine-Tuning**. Biswa Sengupta (single author). arXiv:2605.15394 [cs.LG], v1 14 May 2026. Fixed Llama-3.2-1B-Instruct LoRA harness, natural-language-to-regex; 22 training-time auxiliaries (trajectory-shape regularisation, distributional constraints, predictor/target asymmetry, Fisher-metric Jacobi residuals, a decoder-visible JEPA objective). ## B1. Attacks: indirect prompt injection, corpus poisoning, oracle poisoning, Web3 context manipulation, adaptive attacks

### Takeaway
Retrieved content is an attack surface: a handful of planted documents (5 per target question in PoisonedRAG; 1-10 articles in forecasting; 1-2 graph edits in Oracle Poisoning) suffices for 80-100% attack success, and prompt-level or detector defenses fail under adaptive attackers (all 8 defenses bypassed at >50%).

- Prompt-injection defenses (system prompts, detectors) are not a basis for assurance under adversaries with money at stake: Zhan et al. (8/8 bypassed), Oracle Poisoning (prompt hardening zero effect), CrAIBench (limited protection when memory corrupted).
- "Correct reasoning over corrupted data" (Oracle Poisoning) means chain-of-thought explanations will look sound while the verdict is wrong; explainability to humans is not evidence of correctness.

## B2. Defenses for RAG with numbers (RobustRAG, TrustRAG, ReliabilityRAG, others)

### Takeaway
Provable defenses (RobustRAG isolate-then-aggregate, ReliabilityRAG consistent-majority) assume a minority of corrupted passages; heuristic defenses (TrustRAG clustering) assume poisoned documents cluster tightly. Both assumptions are exactly what coordinated attackers break (Coverage Is Not Containment: attacker seizes all top-k; Corroboration Illusion: fails at k=5).

### Cited Findings
- **RobustRAG**: "Certifiably Robust RAG against Retrieval Corruption". Chong Xiang, Tong Wu, Zexuan Zhong, David Wagner, Danqi Chen, Prateek Mittal. arXiv:2405.15556 (v1 24 May 2024, v2 1 Apr 2026). "isolate-then-aggregate strategy": isolate passages into disjoint groups, generate a response per group, then "securely aggregate"; keyword-based and decoding-based aggregation; formal guarantees against bounded malicious passages. [VERIFIED-PRIMARY (abstract)] — [arXiv abs](https://arxiv.org/abs/2405.15556). Numbers (body, extractor; Mistral-7B-Instruct, Llama-2-7B-Chat, GPT-3.5-turbo): certified accuracy against 1 malicious passage of 10 retrieved: RealtimeQA multiple-choice 69-71%, RealtimeQA short-answer 31-38%, Natural Questions 26-36%, biography generation 38.8-51.2 (LLM-judge score); 1.16-3.65x slower than vanilla RAG; PoisonedRAG/IPI attack success reduced from over 90% to about 10-15%; benign drop 0-7% for QA, 1.2-10% for long-form. Assumes a small fraction of retrieved passages is corrupted and benign passages outnumber malicious. Code link not on page. [VERIFIED-PRIMARY (body, extractor)] — [arXiv HTML v2](https://arxiv.org/html/2405.15556v2)
- **TrustRAG**: "TrustRAG: Enhancing Robustness and Trustworthiness in Retrieval-Augmented Generation". Huichi Zhou, Kin-Hei Lee, Zhonghao Zhan, Yue Chen, Zhenhao Li, Zhaoyang Wang, Hamed Haddadi, Emine Yilmaz. arXiv:2501.00879 (v1 1 Jan 2025, v3 22 May 2025); two-stage "cluster filtering and self-assessment", "plug-and-play, training-free". [VERIFIED-PRIMARY (abstract via extractor)] — [arXiv abs](https://arxiv.org/abs/2605.26754)

### Inferences
- Numbers for RobustRAG/TrustRAG come from random-QA benchmarks with attacks optimized against naive pipelines; none of these evaluations include an adversary who controls many sources or who knows the defense, so they are upper bounds for oracle settings.

## B4. Do multi-agent voting, debate, disagreement signals, and independent retrieval help against poisoned shared evidence?

### Takeaway
Independent aggregation helps when poison is a minority and sources are genuinely independent; debate/deliberation can hurt or amplify persuasion; and when all agents read the same retrieved evidence (as in the AI-oracle design paper) poisoning is a common-mode failure that voting cannot detect. Agent disagreement is a useful uncertainty signal on clean data (unanimity 88% vs split vote 58%) but there is no demonstration that it detects poisoning.

### Cited Findings
- **Multi-agent AI oracles for prediction markets**: "Design and Evaluation of Multi-Agent AI Oracle Systems for Prediction Market Resolution", Tarun Kota, arXiv:2605.30802, 29 May 2026, 34 pages. 1,189 resolved KalshiBench questions; GPT-5 Nano, DeepSeek V3, Llama-3.3-70B; evidence from Exa retrieval filtered by publication date; confidence-weighted voting 83.43% (about +1 pp over best single model; +1.01 pp per body); deliberative consensus about 76% ("error propagation"/"persuasive error propagation"). Body (extractor): all agents receive identical evidence ("shared-evidence control"); unanimous agreement 88.34% accuracy covering 79.6% of questions; 2-1 split 57.82%; unanimous high-confidence 97.87% covering nearly half; cross-model error correlation r=0.529-0.689; 14% of questions fail under all architectures; adversarial robustness and evidence-injection attacks listed only as future work (Sec. 7.2); code/cached evidence packets stated available (Appendix A). Proposes hybrid AI-human routing on disagreement. [VERIFIED-PRIMARY (abstract + body, extractor)] — [arXiv abs](https://arxiv.org/abs/2605.30802), [HTML](https://arxiv.org/html/2605.30802v1)

Designed for natural conflicts, not adversarially optimized poison. Code: [HanNight/RAMDocs](https://github.com/HanNight/RAMDocs). [VERIFIED-PRIMARY (abstract)] — [arXiv abs](https://arxiv.org/abs/2504.13079)
- **Debate is attackable by one persuasive agent**: "When collaboration fails: persuasion driven adversarial influence in multi agent large language model debate", Kraidia et al., Scientific Reports 16, 11640 (8 Apr 2026): a single adversarial agent cuts accuracy by 10-40%, raises agreement on wrong answers by over 30%, influence grows over rounds; more agents, more rounds and prompt warnings did not reliably help; weaker models (GPT-3.5, Llama, Yi) more susceptible than GPT-4o. [VERIFIED-PRIMARY (article page, extractor)] — [Nature](https://www.nature.com/articles/s41598-026-42705-7)
- **Isolate-then-aggregate** (independent processing of passages/sources): RobustRAG certified results when the corrupted fraction is small (B2); Corroboration Illusion shows the same scheme "effective only when poison is minority (k=1); fails at k=5 where poison holds the median" ([HTML](https://arxiv.org/html/2609.22246v1)); Coverage Is Not Containment shows an attacker can seize all 10 top-k slots ([HTML](https://arxiv.org/html/2608.16044)).
- **Independent/cross-source verification**: in Oracle Poisoning, multi-tool cross-verification cut blind trust from 100% to 0-25% by surfacing contradictions between data sources ([HTML](https://arxiv.org/html/2605.09822)); Cordon-MAS separates extraction, cross-source auditing and answer generation (92.4% relative ASR reduction, [abs](https://arxiv.org/abs/2605.26754)); Hall recommends "diverse, redundant sources" ([a16z](https://a16zcrypto.com/posts/article/ai-judges-scale-prediction-markets/)).
- Latent-channel angle: a malicious agent in a KV-sharing team can inject falsehood invisibly (see A2: [2606.28958](https://arxiv.org/abs/2606.28958), [2605.28214](https://arxiv.org/html/2605.28214v1)).

### Inferences
- Disagreement-as-detector is untested for poisoning: Kota measures disagreement on clean data with shared evidence, where a poisoned shared evidence set would produce unanimous wrong answers (my inference; shared evidence induces correlated agreement). Similarly the Corroboration Illusion shows the model counts planted articles as independent corroboration.
- Independent retrieval per agent helps only if retrieval channels have independent failure modes (different corpora/search providers/operators). Independent agents hitting the same crawlable web inherit the same planted documents (Coverage Is Not Containment). No paper found tests per-agent independent retrieval against a budgeted attacker.
- Debate/deliberation should not be used as the aggregation step in an adversarial setting (Kota: ~76% vs 83.43%; Sci. Rep.: single adversary shifts consensus); independent voting with reliability weights and human escalation on split votes is the better-supported pattern, but still not shown robust to adaptive evidence poisoning.

### Gaps
- No work found that tests agent-disagreement as a poisoning detector, or per-agent independent retrieval across disjoint sources against a budgeted adversary.
- Kota's paper does not run attacks; ReliabilityRAG, PRA-RAG, Socrates-RAG not tested here.
- Not covered: Sybil-resistant source weighting, cryptographic evidence attestation (TLS-notary style), and economic analyses of the cost to corrupt evidence vs payout.
